Two minutes from here to a scoot window.

## Try it in your browser

You need [Docker](https://docs.docker.com/get-started/get-docker/). Nothing else is installed.

<Steps>

1. Start the container.

   ```sh
   docker run --rm -p 127.0.0.1:6080:6080 ghcr.io/scoot-sh/try-scoot
   ```

2. Open `http://127.0.0.1:6080` in your browser.

3. Click the desktop. One terminal is already open.

4. Press `Alt+Return`. A second terminal opens. This route uses `Alt`
   wherever the rest of the docs say `Super`, because your browser
   keeps `Super`.

5. To stop, press `Ctrl+C` in the terminal where you started the container. `--rm` deletes the container.

</Steps>

VNC has no password here, so the port stays on loopback (`127.0.0.1`).
To reach the desktop from another machine, tunnel over SSH: [Ports and
security](https://github.com/scoot-sh/try-scoot#ports-and-security).

## Or in a window on Linux (Nix)

Already have [Nix](https://nixos.org/download/)? This runs scoot inside
your current desktop and installs nothing:

```sh
nix shell --accept-flake-config github:scoot-sh/scoot nixpkgs#foot --command scoot --nested -- foot
```

Press `Super+Return` for a second terminal; close the window to quit.
If it compiles for minutes, your Nix does not trust the scoot cache
yet: see [Use the binary cache](../binary-cache/).

## Use it every day

<TabItem label="NixOS">

A flake with home-manager gets you the whole
scoot desktop from one switch: the bar, wallpaper, lock, notifications,
launcher, clipboard history, screenshots and screen sharing, all themed
by one look, and rolled back together if you change your mind.

Three files. Change `myhost` to your host name and `alice` to your user
name everywhere below.

<Steps>

1. `flake.nix` adds scoot and home-manager, and loads both sides of
   scoot for your user.

   ```nix title="flake.nix"
   {
     inputs = {
       nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
       home-manager.url = "github:nix-community/home-manager";
       home-manager.inputs.nixpkgs.follows = "nixpkgs";
       scoot.url = "github:scoot-sh/scoot";
     };

     outputs = { nixpkgs, home-manager, scoot, ... }@inputs: {
       nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
         system = "x86_64-linux";
         specialArgs = { inherit inputs; };
         modules = [
           ./configuration.nix
           scoot.nixosModules.scoot
           home-manager.nixosModules.home-manager
           {
             home-manager.useGlobalPkgs = true;
             home-manager.useUserPackages = true;
             home-manager.extraSpecialArgs = { inherit inputs; };
             home-manager.sharedModules = [
               scoot.homeModules.scoot
               scoot.homeModules.scootbar
             ];
             home-manager.users.alice = import ./home.nix;
           }
         ];
       };
     };
   }
   ```

2. `configuration.nix` is the system side: the login-screen entry and
   the system services. Add these lines to the one you have. The cache
   lines save compiling Smithay on the first rebuild.

   ```nix title="configuration.nix"
   {
     programs.scoot = {
       enable = true;
       desktop.enable = true;
       desktop.look = "ginger-night";  # the login screen and system fonts follow it
     };

     nix.settings = {
       extra-substituters = [ "https://scoot-sh.cachix.org" ];
       extra-trusted-public-keys = [
         "scoot-sh.cachix.org-1:QMj7CMw8uqZxrvqqm6SggdxTHz6Q4prt30ydDcXJXCo="
       ];
     };
   }
   ```

3. `home.nix` is your side: the config file, the per-user services,
   and the same look. Create it next to `flake.nix`. Set
   `home.stateVersion` to your NixOS release (do not copy the value
   blindly: it must match your release).

   ```nix title="home.nix"
   {
     programs.scoot = {
       enable = true;
       desktop.enable = true;
       desktop.look = "ginger-night";
     };

     home.stateVersion = "26.05";
   }
   ```

4. Rebuild.

   ```sh
   sudo nixos-rebuild switch --flake .#myhost
   ```

5. Log out. Pick **scoot** on your login screen.

</Steps>

Your other sessions stay. To undo, set `desktop.enable = false;` in
both files and rebuild, or boot the previous generation.

Every snippet on this site is titled with the file it goes in. Most
desktop options are titled **configuration.nix and home.nix**: each
side does its half (the system installs the service, your user runs
it), so set them in both.

On real hardware with a GPU, the same default package scans out through
it — nothing to pick — once the OS provides the drivers
(`hardware.graphics.enable = true;` on NixOS). VMs
and containers stay on the default.

The login screen, every piece and every option: [The scoot
desktop](../../desktop/).

</TabItem>
<TabItem label="Nix on another Linux">

Nix on another distro gets the themed desktop from home-manager on its
own: the config, the bar, the user services and the look. Your distro
keeps the login screen.

<Steps>

1. Turn on the [binary cache](../binary-cache/) first, so Nix
   downloads instead of compiling.

2. A standalone home-manager flake:

   ```nix title="flake.nix"
   {
     inputs = {
       nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
       home-manager.url = "github:nix-community/home-manager";
       home-manager.inputs.nixpkgs.follows = "nixpkgs";
       scoot.url = "github:scoot-sh/scoot";
     };

     outputs = { nixpkgs, home-manager, scoot, ... }@inputs: {
       homeConfigurations.alice = home-manager.lib.homeManagerConfiguration {
         pkgs = nixpkgs.legacyPackages.x86_64-linux;  # aarch64-linux on ARM
         extraSpecialArgs = { inherit inputs; };
         modules = [
           scoot.homeModules.scoot
           scoot.homeModules.scootbar
           ./home.nix
         ];
       };
     };
   }
   ```

3. The same `home.nix` as on NixOS, plus who you are:

   ```nix title="home.nix"
   {
     programs.scoot = {
       enable = true;
       desktop.enable = true;
       desktop.look = "ginger-night";
     };

     home.username = "alice";
     home.homeDirectory = "/home/alice";
     home.stateVersion = "26.05";
   }
   ```

4. Apply it.

   ```sh
   nix run home-manager -- switch --flake .#alice
   ```

</Steps>

To get scoot on your login screen too, also run the [Any
Linux](#use-it-every-day) script with `--system --no-bar`: it adds the
session entry, and home-manager keeps the bar and the config. The
login entry then runs the script's scoot, not the flake's, so keep the
two on one version (the flake follows `main`; the script installs the
newest tagged release, so they can differ). Two
pieces need your distro rather than home-manager: the lock screen's PAM
service and backlight access ([details](../../desktop/#home-manager)).

</TabItem>
<TabItem label="Any Linux">

One command installs scoot, the wallpaper daemon and the bar from
GitHub, checks each binary against the release's checksums, and tells
you which system libraries are missing. Any distro with glibc 2.36 or
newer (Debian 12, Ubuntu 24.04, current Fedora, Arch, openSUSE),
x86_64 or aarch64. It never replaces a scoot that a distro package
installed.

```sh
curl -fsSL https://www.scoot.sh/install.sh | sh -s -- --system --look ginger-night
```

You need `curl` (or `wget`) and `sh`: `sudo apt install curl` on
Debian and Ubuntu. Silence with a zero exit means the download itself
failed and the script never ran — check the network and run it again.

Minimal Fedora and Arch images ship no usable font, and the bar refuses
to start without one (`no font: none of the usual font files is usable`).
The script names the package for your distro
when that is you (`fonts-dejavu-core` on Debian and Ubuntu, `dejavu-sans-fonts` on
Fedora, `dejavu-fonts` on openSUSE, `ttf-dejavu` on Arch) — or point the
bar at any file with `--font PATH` instead.

The command it prints waits for confirmation; for a non-interactive run,
add `-y` (`apt`, `dnf`) or `--noconfirm` (`pacman`). `--dry-run` lists
the missing libraries and fonts without changing anything.

Then log out and pick **scoot** on your login screen.

- `--system` installs under `/usr/local` and adds scoot to the login
  screen; it asks for `sudo`. Leave it off to install into `~/.local`
  with no root, and start a session from a text console with
  `scoot-session`.
- `--look` installs the five [looks](../../scoot/theming/) under
  `<prefix>/share/scoot/looks` and applies one with `scoot look apply`.
  Your `config.toml` and `bar.toml` are never written, only read: a file
  still identical to an older `--look` run has its look keys removed so
  the layer shows through, and anything else is left alone while `apply`
  names the keys shadowing the look. Under `sudo` the apply runs as the
  invoking user. A re-run that is already up to date still installs the
  catalog and applies a `--look` you name (without downloading
  anything); without `--look` it changes nothing.
- Re-running the script updates: it installs the newest tagged release,
  or says `already up to date (<version>)` and changes nothing
  (`--force` reinstalls anyway). "Up to date" is per destination:
  the script records where it installed (covering `--prefix` and
  `--system`), so re-running with a different `--prefix` installs
  there instead of reporting up to date — and if the installed
  binaries are gone, it reinstalls rather than claiming to be
  current. `--check` only compares the installed version with the
  newest tag, or with the `--version` you name (exit 0 if current,
  10 if an update exists) without installing anything. To run `main`
  instead of a tagged release, use the Nix flake above.
- `--uninstall` (with `--system` if you used it) removes exactly what
  the script installed. Your config stays.

Read the script before you run it:
[install.sh](https://www.scoot.sh/install.sh). Every option:
`sh install.sh --help`.

The lock,
notifications, launcher and screenshots come from your distro: [Build
your desktop](../compose/#any-other-linux-the-parts) has the one
command per distro.

</TabItem>
<TabItem label="From source">

Rust 1.88 or newer. On Debian 13 or Ubuntu 24.04 and newer (older releases do not ship `libdisplay-info-dev`):

```sh
sudo apt install pkg-config libwayland-dev libxkbcommon-dev libinput-dev \
  libdrm-dev libdisplay-info-dev libseat-dev libudev-dev libpixman-1-dev \
  libgbm-dev libegl-dev libdbus-1-dev
git clone https://github.com/scoot-sh/scoot
cd scoot
cargo build --release -p scoot -p scootbar -p scootbg
```

The binaries are in `target/release/`. Copy them to a directory on
your `PATH`. To build `.deb`, `.rpm` or Arch packages yourself, see
[Package scoot offline](../../reference/packaging/).

## Check that it works

<Steps>

1. Show the version. You do not need a running session for this.

   ```sh
   scoot --version
   ```

2. Start scoot in a window.

   ```sh
   scoot --nested -- foot
   ```

3. In the terminal inside scoot, ask scoot for its windows.

   ```sh
   scoot msg windows
   ```

   The output is JSON with one entry: the terminal you typed in.

4. Find the line that names the renderer. scoot prints it in the terminal where you did step 2.

   ```text
   renderer chosen requested=auto source=default tier=cpu reason=nested-unmeasured driver="-" gl_renderer="-"
   ```

   `tier=` is the renderer that draws. `reason=` says why.

</Steps>

All four work — you are done.

## Which build do I need?

One build is enough for everyone: `scoot`. With the default
(`auto`) it resolves to the CPU renderer where there is no GPU and to
the GPU renderer on real hardware, so it is what the script and the
default Nix package install. X11 apps need no different package (the
`xwayland` feature is compiled in; just turn the knob on), and the
deliberate avoidance of all GPU code is a cargo-only build
(`cargo build --no-default-features`), not a published package. Every
build, flag and renderer rule is in [Builds and
renderers](../../reference/builds/); what the binary cache trusts is in
[Use the binary cache](../binary-cache/).
